# ALS 版：検査値写真の取り扱い設計メモ（§10）

> PoC 段階の設計メモ。「本番はこう畳む」方針を固定する。実装ブロッカー扱い。

## 1. なぜブロッカーか

検査値表の写真には、氏名・患者ID・施設名・検査日・検査値が写り込むことが前提で、**要配慮個人情報**に該当する。Vision API への送信は第三者提供・（海外リージョンの場合）越境移転の論点が立つ。

## 2. 同意取得（最低ライン・実装済み）

- 画像を Vision API に送る**前に**、同意モーダルを表示する。
- 同意内容の要点:
  - 検査値表写真には氏名等が写り込みうること
  - 数値抽出のため外部 Vision API（Gemini）へ画像を送信すること
  - 抽出は転記補助であり診断ではないこと
  - 同意はいつでも撤回でき、以後の送信を止められること
- 同意フラグは端末の `localStorage`（`yorisoi_als_lab_ocr_consent`）に保存。撤回 UI は検査値画面に置く。

## 3. マスキング方針

**撮影ガイド（PoC）**
- 送信前にガイドを表示: 「氏名・患者番号・施設名が見える部分は紙や指で隠してから撮る」
- 必須の画面上マスク編集は Phase 1 では任意（未実装でもガイドで代替可）

**本番候補**
- 送信前に矩形マスク編集（氏名欄・バーコード等）
- または端末内で顔・文字領域の簡易ぼかし後に送信

## 4. 保存場所・保持・削除

| 段階 | 画像の置き場 | 保持 | 削除 |
|------|--------------|------|------|
| PoC / デモ | アプリサーバまたは Firestore 相当のユーザ領域に data URI（開発用） | ユーザーが削除するまで | 検査値詳細から個別削除 |
| 本番 | **Cloud Storage（asia-northeast1）** のユーザ専用パス。Firestoreには `photoPath` のみ | 既定 24 ヶ月（要確認）＋ユーザー任意削除 | オブジェクト削除＋メタ削除。撤回時は未送信のみでなく保存済みも削除導線 |

- **写真が source of truth**。OCR 抽出値は補助。後から写真と突き合わせ可能にする。
- サーバログに画像 base64 を残さない。

## 5. モデル / リージョン / 越境移転

- 現行: `@google/genai` / Gemini Vision（`GEMINI_API_KEY`）。リージョンは API 仕様に依存。
- **本番方針**:
  1. 可能な限り **東京（asia-northeast1）リージョン固定**の Vision / Generative API を選定する
  2. やむを得ず海外処理になる場合は、プライバシーポリシーに越境移転・第三者提供を明記し、同意文に含める
  3. 利用モデル名・処理場所を本メモとアプリ内「同意の詳細」に同期する

## 6. silent auto-commit 禁止

抽出結果は必ず「写真と並べて確認 → ユーザーが1タップ確定」するまで永続化しない。確認なしの自動保存は行わない。
